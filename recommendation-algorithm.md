# Алгоритм объяснимого подбора

Алгоритм не использует ИИ, вероятности или скрытые веса. Чистая функция
evaluateRecommendation находится в includes/recommendations.php.

## Входные данные

Профиль: education_level (по умолчанию spo), course, birth_date, specialty_id,
интересы из student_interests. Уровень образования можно изменить в student/profile.php.
Возраст — полное число лет на текущую московскую календарную дату; сравнение учитывает
день рождения. Возраст на дату участия может отличаться: это отдельно оговорено в интерфейсе.
Образовательная организация не является самостоятельным условием допуска в текущей схеме.

Мероприятия: только publication_status=published. Для каждого выбирается запись
competition_eligibility соответствующего уровня образования. Ограничения других
уровней не смешиваются с ней. Допустимые специальности берутся из
competition_eligibility_specialties; направления — из competition_categories.

## Решение

1. «Не подходит», если имеется хотя бы одно подтверждённое несоответствие:
   is_allowed=0, возраст/курс за известной границей или специальность отсутствует
   в непустом списке допустимых специальностей. Каждая причина выводится текстом.
2. «Возможно подходит», если запрета нет, но есть неопределённость: отсутствует
   запись eligibility, is_allowed=NULL, в профиле нет данных для известного
   ограничения, обе возрастные или обе курсовые границы отсутствуют, либо есть
   дополнительный текстовый комментарий, который нельзя проверить автоматически.
3. «Подходит», если допуск подтверждён и все применимые проверки проходят без
   таких неопределённостей. Односторонняя известная граница проверяется как есть;
   NULL на другой стороне не считается запретом.

Пустой список специальностей не запрещает участие. Нет совпадения интересов —
тоже не запрет: интересы используются только при сортировке. Объяснения выводятся
для всех проверок, включая отсутствующие данные. «Не подходит» имеет приоритет
над любым числом неизвестных условий.

## Сортировка

Ключи применяются последовательно:

1. Подходит → Возможно подходит → Не подходит.
2. Активная или предстоящая регистрация раньше закрытой, отменённой и неизвестной.
3. Больше совпадающих интересующих категорий выше.
4. Более близкий дедлайн выше, неизвестный — после известных.
5. ID мероприятия для стабильности одинаковых результатов.

Статус регистрации не меняет вывод об условиях допуска: он отображается отдельно.
Мероприятие с подходящими условиями, но закрытой регистрацией не обещает возможность
подать заявку. Даты рассчитываются сервером в UTC и показываются по Москве.
Пользователь может фильтровать по результату подбора; пагинация — 12 записей.

Связанные данные загружаются несколькими общими SQL-запросами, без запроса на каждую
карточку. Сортировка выполняется PHP; для очень большого каталога потребуется
перенести предварительный отбор и ранжирование в SQL, сохранив те же правила.
